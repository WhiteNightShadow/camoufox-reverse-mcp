## 版本说明

这一版处理 [@Moojing-jianchuan](https://github.com/Moojing-jianchuan) 提的 [#19](https://github.com/WhiteNightShadow/camoufox-reverse-mcp/issues/19)–[#25](https://github.com/WhiteNightShadow/camoufox-reverse-mcp/issues/25)，修了复核时发现的 preset 钩子装在隔离世界的问题，并合并他的 [#26](https://github.com/WhiteNightShadow/camoufox-reverse-mcp/pull/26)（`stage_break`、`trace_session`）。`instrumentation` 有两个默认值变了：`rewrite_calls` 改为关闭，`max_file_size` 从 200KB 提到 2MB。

## 主要变更

- 插桩（#19 #20 #21 #25）：默认只改写成员读取。调用改写会让被调函数读到的 `caller` 变成 null、最大递归深度下降，指纹脚本可能因此算出不同的值，所以改为需要时再打开。`max_file_size` 默认 2MB；原样放行的文件和改写处数到上限的文件，`status` 和 `log` 会逐个列出原因和建议值。新增 `action="rewrite_source"`：不开浏览器改写本地源码，结果在 Node、vm、jsdom 里都能运行。每条事件都带 `seq`，平坦化状态里的事件还带 `stage`；`log` 支持 `after_seq`、`seq_window`、`stage` 切片，并返回日志满 20000 条后丢掉的条数 `dropped`。
- iframe 与探针（#23 #24）：同源子 frame 里的探针和插桩事件写进顶层日志，带 `frame_url`、`frame_depth`，页面建了又删掉的 about:blank iframe 也不会丢。`hook_jsvmp_interpreter` 返回 `coverage`，写明这个探针能记录和记录不到的范围，例如直接调用 `ctx.measureText()` 记不到；日志里没有某个调用，不等于页面没调用。
- preset 钩子：`inject_hook_preset` 和 `navigate(pre_inject_hooks=...)` 的 7 个 preset 以前装在隔离世界，页面自己发的 XHR、fetch 和 cookie 读写一条都记不到，现在装到页面主世界。同时改掉了在主世界里会影响页面的写法：把 XHR 和 fetch 定义成不可改写、往请求对象上挂字段、`JSON.stringify` 重复序列化、往页面控制台打印。`remove_hooks` 能还原它们，`get_request_initiator` 改读主世界的日志。
- 环境与调试（#22 #26）：`compare_env` 的 canvas、WebGL、audio 以前返回空对象，现在有值；传 `output_path` 可以导出完整环境包，包括 navigator 全部 getter、getComputedStyle 的属性和值、CSS 声明的原型名和 enumerable 标志、完整的 canvas toDataURL、WebGL 参数和扩展、audio、storage 键名、iframe 对照和 timing。合并 #26：`stage_break` 对指定状态记录参数、返回值和调用栈的有界快照，布下的状态刷新后仍然生效；`trace_session` 录制可回放的 Playwright trace。

## 兼容性

- 默认不再产生 `tap_call`、`tap_method`、`tap_call_err` 事件，`hot_methods` 和 `hot_functions` 为空；需要时安装时传 `rewrite_calls=True`。200KB～2MB 的脚本以前原样放行，现在会被改写；改写放在后台线程，不再卡住 MCP 的其他请求。
- 插桩运行时改用 `globalThis`（浏览器里就是 `window`），它的全局变量不再出现在 `Object.keys(window)` 里。每条事件都带 `seq`，以前只有开 `include_source_site` 时才有。同源 iframe 里的事件改写进顶层日志，以前留在 iframe 自己的日志里。
- preset 装在页面主世界，页面脚本能察觉被替换的函数，在签名型反爬的页面上和 proxy 探针一样不要用。`inject_hook_preset(persistent=False)` 改为只装到当前文档，以前反而只对之后的导航生效。xhr 记录改在发出请求时写入，没收到响应的请求也会记下。`cookie` 和 `cookie_hook` 两个名字在两个入口都能用。
- 工具从 39 个变成 41 个，新增 `stage_break` 和 `trace_session`。`compare_env` 不传 `output_path` 时返回结构不变。

## 验证

- 本机 Python 3.12、Camoufox 0.5.9、Playwright 1.62.0：540 passed、2 skipped。新增 36 个测试，其中 6 个是合并 #26 前补的，在作者原提交上都会失败；其余覆盖默认值、跳过和截断记录、离线改写后在 Node vm 里运行（`window` 不是全局对象时也能运行）、`seq`/`stage`/`dropped` 与切片、子 frame 事件汇总到顶层、探针覆盖说明，以及 7 个 preset 在主世界里记录、不改变页面行为、能还原。
- 真实浏览器（Camoufox 0.5.9，无头，本地页面）47 项检查全部通过：
  - 插桩：330KB 的脚本按默认值被改写，2.7MB 的脚本原样放行，并列出原因和建议值；状态事件和带 `stage` 的读取都在，`after_seq`、`seq_window`、`stage` 切片结果正确；刷新前布下的 `stage_break` 在页面加载时就记到，调用栈里没有探针自己的帧；同源 iframe 里的脚本事件在 iframe 删掉后仍在顶层日志里。
  - 探针：proxy 和 transparent 两种模式下，页面建了又删掉的 about:blank iframe 里的读取和调用都进了顶层日志，`seq` 跨 frame 连续。
  - preset：页面自己的 XHR（含请求头）、fetch、cookie 读写和 btoa 都记到了，preset 的全局变量不出现在 `Object.keys(window)` 里；`get_request_initiator` 拿到了 XHR 的调用栈；`remove_hooks` 之后 XHR、fetch、cookie 恢复成原生函数；`navigate(pre_inject_hooks=["xhr", "cookie_hook"])` 同样生效。
  - `compare_env`：canvas、WebGL、audio 都有值；环境包 155KB，CSS 属性数和 for-in 数与页面主世界一致；`trace_session` 写出了 109KB 的 trace。
- #26 的作者分支加上修复提交后，CI 全部通过。
