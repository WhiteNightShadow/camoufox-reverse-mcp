## 版本说明

这一版解决「同站点脚本每次请求都换、opcode 编号随 build 变」这类目标上的三个硬摩擦：源码级正则插桩看不见命中、mock 响应塞不进几十万字节的改造脚本、断点绑死在每次都会变的 URL/sourceId 上。三个功能都向后兼容，原有参数与默认行为不变。

## 主要变更

- `instrumentation` 新增 `inject`：`[{find, before|after, group}]` 按正则在同一脚本内全部命中处插入语句，`$1..$99` 引用捕获组，每组命中次数在 `inject.groups[].matches` / `status.inject_hits` / `log` 里可见；语句化包裹 + 字面量区逐处跳过 + 解析校验兜底，`case` 标签前的 `before` 自动挪到冒号后，保证插入不破坏原脚本语法
- `intercept_request` 的 `mock_response` 新增 `body_file`：UTF-8 读取、相对路径按服务器工作目录解析、与 `body` 互斥、错误可读、每次请求重读；`headers` 缺省按后缀推 `content-type`，所以 270KB 改造版 `tdc.js` 可以直接 mock 进页面
- `rdp_debugger(action="set_breakpoint")` 新增 `url_pattern` + `find` + `occurrence`：把正则命中的字符偏移换算成 `line/column`，`reload` / `enable` 重建 thread 后自动重新 `sources()` → 重算 → 重下，正则不再命中时写进 `reapply_failed`（`reason: "regex not found"`）
- `sources` / `source` / `breakable_*` 也接受 `url_pattern`；`status` 的断点带 `locator`，补 49 条单测

## 兼容性

- 与 `v1.11.1` 兼容：42 个 MCP 工具名称不变，`mode='ast'/'regex'`、`tap_stage_calls`、`filter_*`、`source`/`source_url` + `line`/`column`、`modify`/`block`/`log` 行为不变；新增参数都有默认值
- 新增模块 `utils/regex_inject.py`（纯逻辑，不依赖浏览器）
