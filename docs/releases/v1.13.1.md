# v1.13.1（2026-11-25）— `list_network_requests` 的 URL 预览不再静默截断

## 背景

`list_network_requests` 返回的 `url` 字段固定按 `[:200]` 截断，且不带任何标记。超过 200 字符的 URL（带 `msToken`、`verifyFp`、`a_bogus` 一类查询参数的请求几乎必然超长）尾部会整段消失，返回值看起来仍是一条完整 URL。

实测踩坑：抓一个电商 H5 商品详情页时，列表里显示

```
.../promotion/pack/h5/?is_h5=1&...&msToken=Fou1lx93Nic_d1LpRNy
```

看起来到 `msToken` 就结束、没有签名参数；改用 `get_network_request(request_id=58)` 取完整值才看到尾部还有 `&a_bogus=YyUdfc23Msm1kYrUQ7kz97LZMob0YW51gZEzjvsaGtqy`。因为少了这一截，把「请求带了签名仍被拒」误判成「请求没带签名」，方向偏了一轮。

只要 URL 里带签名、token 或游标，这个缺陷都会误导判断，而且现场很难察觉——丢失的部分刚好像正常结尾。

## 变更

- 截断处补 `…`，新增 `url_truncated`（bool）与 `url_length`（真实长度），语义与既有的 `body_truncated` 对齐
- `list_network_requests` 的 docstring 增加约束：不要从被截断的预览里读取查询参数、签名或 token，先用 `get_network_request(request_id=...)` 取完整 URL
- 预览上限抽成模块常量 `URL_PREVIEW_CHARS`（仍为 200），输出体积不变，只增加可观测性

## 兼容性

纯增量：新增两个字段，`url` 在长度 ≤ 200 时与旧版逐字节一致；超过 200 时旧行为是静默截断，新行为多一个 `…` 后缀。依赖 `url` 做精确字符串比较的调用方应改读 `get_network_request` 的完整值。
