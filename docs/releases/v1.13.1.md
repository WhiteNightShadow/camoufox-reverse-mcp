## 版本说明

v1.13.1 修复请求摘要中的 URL 静默截断问题：`list_network_requests`（及 `wait_for(mode="request"|"auto")` 返回的请求摘要）此前将 `url` 固定按 `[:200]` 截断且不附带任何标记，携带长查询串、动态签名或游标令牌的请求（如 `https://api.example.test/v2/item/detail?...&nonce=...&sig=...`）在列表里会被悄然削去尾部，极易把「请求已带签名但仍被拒绝」误判为「请求未携带签名参数」。新版本保持 200 字符预览上限，同时在截断处显式追加 `…` 并暴露 `url_truncated` 与 `url_length`。

## 主要变更

- **网络请求摘要显式标记 URL 截断（`list_network_requests` / `wait_for`）**：共享 `utils/evidence.py` 中的 `URL_PREVIEW_CHARS = 200` 与 `url_preview_fields` 归一化逻辑；长度超过 200 字符时预览以 `…` 结尾并置 `url_truncated=True`、`url_length=<完整字符数>`，与 `body_truncated` 语义一致，同时清洗孤立 UTF-16 代理项并兼容缺省 `url` 字段。
- **全量 URL 过滤与取证边界说明**：`url_filter` 与 `url_contains_domain` 仍针对完整原始 URL 匹配（超过 200 字符处的查询参数同样可被过滤命中）；工具 docstring 与参考文档明确要求在读取查询参数、签名或令牌前先调用 `get_network_request(request_id=...)` 获取完整 URL。
- **单测与发版模板回归**：补齐 `len < 200`、`len == 200`、`len == 201`、尾部查询参数过滤、孤立代理项与 `wait_for` 请求摘要一致性单测，并在 `tests/test_docs.py` 中纳入当前版本发版说明模板校验。

## 兼容性

- 纯增量兼容：43 个注册工具名称与入参不变；`url` 在长度 `<= 200` 时与旧版逐字符一致，超过 200 字符时追加 `…` 后缀并附带 `url_truncated`、`url_length` 字段。需要精确比较完整 URL 的调用方请使用 `get_network_request(request_id=...)`。
