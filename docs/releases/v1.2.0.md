## 版本说明

本次迭代处理
[Issue #10](https://github.com/WhiteNightShadow/camoufox-reverse-mcp/issues/10)
中可以通用化的部分：源码级 tap 事件此前只有属性、函数、值和时间，无法稳定关联到
被拦截脚本中的执行位置，也不便于对齐浏览器与沙箱日志。

用户材料证明了执行点关联的实际需求，但没有提供 AST 转换器、原始脚本或可运行最小
复现；其中 `p`、`sbl`、`p=<target>` 和入口地址属于单个 VM 的约定，PC 范围、
VM0/VM1 与源码偏移说明也不能相互印证。因此本版本不执行任意用户 AST 脚本，
不自动猜测 PC/opcode，也不把混淆后 JS 位置描述成保护前源码位置。

## 新增能力

- `instrumentation(action="install")` 新增默认关闭的 `include_source_site`。
- AST 与 regex 模式为每个实际保留的 tap 生成内容寻址、跨 tag 稳定的 `site_id`。
- 开启后，已记录事件增加从 0 递增的 `seq`，表示同一 runtime 内成功写入日志的
  追加顺序；采样、过滤或页面重载会影响或重置该序列。
- `instrumentation(action="log")` 返回 `source_sites` sidecar，包含解码后原始脚本的
  SHA-256、URL、Unicode code point 半开区间；AST 模式同时包含 1-based 行号和
  0-based 列号。
- 日志摘要补齐文档已描述但此前遗漏的 `hot_functions`，并在有站点数据时返回
  `hot_sites`。

## 兼容性

- `include_source_site=False` 时，现有 tap 事件字段保持不变。
- 新字段和 sidecar 均为增量输出，不改变现有 `install/log/stop/reload/status` 动作。
- 停止 route 后 sidecar 仍可解析已有日志；`close_browser()` 或
  `reset_browser_state(clear_active_routes=True)` 会显式清理 route 与站点 registry。
- 安装期间仍沿用按 URL 的改写缓存；若同一 URL 的脚本内容发生热更新，应先
  `stop` 再重新 `install`，以重新获取源码和生成 content id。
- 源码站点表示拦截到的混淆后 JavaScript 位置，不等同于 VM PC、opcode 或保护前
  业务源码位置。
- 本次只修改 MCP 的 Python 改写层与注入 runtime，不涉及 Camoufox/Firefox
  底层，无需重新编译或替换 `camoufox-reverse`。

## 验证

- Python 3.12 本地完整测试：`114 passed`。
- 额外本地验证的两种独立结构通用 VM 样例均保持原始返回值，站点事件 `seq`
  连续递增。
- 额外本地 330,026 字节、11,000 个成员访问的压力样例完成 AST 改写并可重新解析；
  11,000 个 `site_id` 全部唯一。
- 覆盖 AST/regex、默认关闭、Unicode 非 BMP 偏移、内容稳定哈希、Schema、日志
  sidecar、AST→regex fallback、多 URL、route 停止后解析、截断 hot site、
  `hot_functions` 与运行时序列回归。
