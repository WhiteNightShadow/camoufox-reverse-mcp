# camoufox-reverse-mcp v1.4.0

This release pairs with Camoufox Reverse
`v152.0.4-beta.30-reverse.4` and makes native property tracing correct,
interactive, and safe across concurrent MCP/browser instances. Existing
default launches, Camoufox 0.4.x, and official browsers remain supported.

## Native trace controls

- `trace_property_access(action=...)` now supports:
  - `capture`: existing blocking fresh window;
  - `start`: start a fresh window and return immediately;
  - `stop`: native drain acknowledgement followed by aggregation;
  - `query`: read the current window without changing state;
  - `clear`: stop and clear only the current launch's traces/snapshots;
  - `status`: report live native acknowledgements and I/O errors.
- Add `filter_kind=get|set|call` and `filter_site`.
- Merge extended reverse.4 events by Unix microseconds, expose the native site,
  process/session, sequence, and correct operation kind, and cap timeline bucket
  allocation.
- Empty results include `coverage.negative_result_is_conclusive=false` because
  PropertyTracer is a fixed 75-site native coverage set, not arbitrary
  JavaScript property tracing.
- Historical-file queries retain that coverage boundary and report the original
  per-process event cap as unknown rather than treating an empty filter as
  conclusive.

## Isolation and reliability

- Allocate a private run directory for every traced browser launch.
- Control, cleanup, trace files, and safe value snapshots are scoped to that
  run; concurrent MCP instances cannot stop or delete each other's data.
- Reverse.4 uses a run-level desired state plus per-process native status
  acknowledgement. New Firefox content processes honor stop/start transitions,
  and write/open failures are reported instead of returning an apparently
  complete result.
- Status separates acknowledgement support from the number of native processes
  that actually wrote a valid acknowledgement; a missing status file is never
  reported as ready.
- Reject stale control files by live PID. Windows uses
  `OpenProcess/GetExitCodeProcess`; it never calls destructive `os.kill(pid, 0)`.
- A single async action lock serializes start/stop/capture/clear transitions.

## Capability and compatibility

- `check_environment()` separates `installed`, `trace_capable`, and
  `trace_active`, and returns selector, protocol, hook count, features, run
  directory, and stale-control diagnostics.
- Parse the complete browser capability marker while accepting protocol-v1
  core fields and markerless legacy 135 live handshakes.
- `launch_browser` adds optional `trace_objects` and `trace_max_events`.
- An official browser identified by Camoufox 0.5 metadata with
  `enable_trace=True` now launches normally without injecting an unsupported
  config or disabling its sandbox.
- Camoufox 0.4 official 135 and early markerless custom 135 builds cannot be
  distinguished before launch. To preserve legacy custom-build compatibility,
  an explicit trace request still attempts the old live handshake; the default
  `enable_trace=False` path remains unchanged.
- Engine tracing still temporarily disables the Firefox content sandbox so
  content processes can write the private run. Normal launches are unchanged.

## Snapshot semantics

`collect_values=True` remains accepted for compatibility but is now explicitly
reported as `snapshot_values`: a safe post-trace JS snapshot, not an event-time
value. Cookie, Canvas, WebGL, AudioContext, and other sensitive or side-effectful
paths are listed in `values_skipped` instead of being invoked or returned.

## Validation

- Python unit suite covers runtime markers, stale controls, markerless 135,
  run isolation, Windows PID probing, global ordering, timeline bounds,
  start/stop actions, and native control acknowledgement.
- Browser release tests cover the 75-site fail-closed injector, typed events,
  buffered multi-thread writes, drain, desired state, installer verification,
  and build-state isolation.
