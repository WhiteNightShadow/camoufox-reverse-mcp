## 版本说明

修复 `launch_browser` 覆盖启动参数的问题：配在客户端里的 `--headless`、`--locale` 等参数，现在调用它时也会生效。没配这些参数的用户不受影响。

## 主要变更

- `launch_browser` 没传的参数改为沿用启动参数，`--headless`、`--os`、`--locale`、`--geoip`、`--humanize`、`--block-images`、`--block-webrtc` 不再被工具默认值覆盖，结果和浏览器自动启动时一致。调用时传了的参数仍然优先。这个问题从 v1.0.0 起就存在，之前只有 `--proxy` 不受影响。
- README 改版：围绕安装、工具和启动参数组织，版本记录移到 `CHANGELOG.md`，工具表和使用场景移到 `docs/TOOLS.md`。工具表补上漏写的 3 个工具，英文版工具数由 36 改为 39。
- 新增 MIT `LICENSE` 文件。项目一直声明 MIT，但仓库里没有许可证文本，GitHub 识别不到。

## 兼容性

- 没配启动参数的用户，以及调用时把这些参数都传了的用户，行为不变。
- 配了启动参数、调用 `launch_browser` 时又没传的用户，升级后配置开始生效。例如配了 `--headless` 就不再弹出窗口。
- 配了 `--geoip` 的用户要注意：`launch_browser` 现在会真的查询公网 IP，查不到时返回错误，和浏览器自动启动时一样，之前是静默忽略。不需要时去掉这个参数，或在调用时传 `geoip=false`。
- 参数名不变。`launch_browser` 的 7 个参数不再声明 `default`，因为没传时的取值由启动参数决定，类型不变，严格校验的客户端仍然兼容。其余 38 个工具的定义与 v1.9.0 一致。

## 验证

- 完整离线回归在三组依赖上通过：Camoufox 0.4.11 与 Playwright 1.52.0 为 465 passed、3 skipped，0.5.5 与 1.60.0、0.5.9 与 1.62.0 均为 466 passed、2 skipped。
- 新旧版本对比：用 54112 组启动参数和工具参数的组合，比较实际传给 Camoufox 的值。没配启动参数的 7957 组、参数全部传入的 16727 组都和 v1.9.0 完全相同，其余差异只出现在配了启动参数又没传的项上。
- 真实浏览器在三组依赖上验证：配好启动参数后不传参调用 `launch_browser`，页面读到的系统、语言、图片拦截和 WebRTC 状态都和自动启动一致；传参后能够覆盖；没配启动参数时结果和 v1.9.0 相同。`--geoip` 在网络正常和查不到公网 IP 两种情况下，都和自动启动的表现一致。
- 真实 MCP 客户端用 README 的验证提示词跑通：配好 `--headless --os windows --locale en-US` 后，模型不传参数或只传 `headless` 时，启动都用上了这些参数，返回标题 `Example Domain`，没有工具报错。
