## 版本说明

修复 `hook_jsvmp_interpreter` 的两个老问题：探针装在隔离世界，页面脚本的读取和调用一条都记录不到；proxy 模式会无限递归，装上后同一环境里再执行 JS 就报错。现在探针装在页面主世界，日志用 `evaluate_js("window.__mcp_jsvmp_log || []", world="main")` 读取。

## 主要变更

- 探针改装到页面主世界，`hook_jsvmp_interpreter` 和 `navigate(pre_inject_hooks=["jsvmp_probe"])` 都是。在 Camoufox 0.5.x 上，持久安装走主世界通道，在页面脚本之前生效，页面的 CSP 禁止 eval 也不受影响；其他情况退回 `wrappedJSObject.eval`，见兼容性。
- proxy 模式修复无限递归。探针替换了 `Function.prototype.call/apply/bind`，内部却还在调 `.call`，从 v0.4.0 起装上后同一环境里再执行 JS 就报 too much recursion，不带 `script_url` 时工具调用会卡到客户端超时。现在内部一律用保存好的 `Reflect.apply`，也不再记录探针自己的调用。
- `remove_hooks` 按原样还原探针替换过的函数、getter 和全局对象。以前 proxy 模式只还原全局对象，还原成了普通属性，`Function.prototype.call` 等一直留着包装函数。
- 探针自己的全局变量改为不可枚举。安装提示只在文档开头打印或放进工具返回值，页面代码拦截 console 也看不到。

## 兼容性

- 日志读法变了：要加 `world="main"`，用默认的隔离世界读会得到空数组，以前的版本在隔离世界里也一直是空的。工具返回值新增 `world` 和 `read_with` 说明读法，transparent 模式还会返回替换了多少个 getter。
- 探针现在真的改动了页面：proxy 模式替换 `Function.prototype.call/apply/bind`、`Reflect.*`、`Date.now`、`performance.now` 和 `Math.random`，并给全局对象套 Proxy；transparent 模式替换原型上的 getter，`Function.prototype.toString.call(getter)` 能看出是 JS 源码。对检测敏感的目标仍应先用 `instrumentation(action="install")`。
- 实测 Camoufox 0.5.5 和 0.5.9 会在主世界运行带 `mw:` 的初始化脚本，0.4.11 不会。0.4.x 或连接的外部浏览器没开 `main_world_eval` 时，持久安装改走 `wrappedJSObject.eval`，页面的 CSP 禁止 eval 就会被拦下，原因打印在 `get_console_logs` 里；这时页面加载后再调用 `hook_jsvmp_interpreter` 仍能装上。
- 工具参数不变，39 个工具里只有 `hook_jsvmp_interpreter` 的说明文字有改动。

## 验证

- 完整离线回归在三组依赖上通过：Camoufox 0.4.11 与 Playwright 1.52.0 为 481 passed、3 skipped，0.5.5 与 1.60.0、0.5.9 与 1.62.0 均为 482 passed、2 skipped。
- 新增 8 个测试：在 Node 里按浏览器的样子准备 `navigator`、`screen` 等对象，装上探针后跑页面代码。`call/apply/bind`、`Reflect.apply`、绑定函数 `new`、抛出异常、读 getter 的结果都和不装时一样，只记录目标脚本，卸载后函数和 getter 与原来是同一个对象。v1.9.2 的 proxy 探针跑同样的代码直接栈溢出。另有 17 种故意改坏的写法，都会被这些测试拦下。
- 真实浏览器（三组依赖，无头，本地页面加载两个脚本，只过滤其中一个）：先装再导航、页面加载后再装和 `pre_inject_hooks` 三种方式都记录到了目标脚本的读取和调用，没有混进另一个脚本。transparent 先装记录 14 条、后装 12 条；proxy 记录 91 条，覆盖 call/apply/bind、`Reflect.apply`、Proxy 读取和 `Date.now` 等。页面里的计算结果和不装时一样，之后执行 JS 正常，不带 `script_url` 时工具调用不再卡住。`remove_hooks` 后 `Function.prototype.call` 和 getter 恢复成原生，`window.navigator` 恢复成访问器；页面可枚举的全局变量里没有 `__mcp_` 开头的。带 `script-src 'self'` CSP 的页面上，0.5.5 和 0.5.9 的持久安装照样生效；0.4.11 和模拟没有主世界通道时，持久安装被拦下并在控制台说明原因，页面加载后再装仍然有效。三组依赖共 45 个场景，结果都和上面一致。
- 用 v1.9.2 在类似页面上对照：transparent 一条都记录不到；proxy 装上后执行 JS 报 too much recursion，不带 `script_url` 时卡到超时。
