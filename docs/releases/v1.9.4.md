## 版本说明

`instrumentation(action="install")` 新增 `tap_stage_calls`：把控制流平坦化 JSVMP 的分发调用改写成逐状态的 `tap_stage` 事件。真实浏览器和本地补环境用同一份输入各跑一次，就能按状态号逐段对照，找出从哪一步开始不一致。功能由 [@Moojing-jianchuan](https://github.com/Moojing-jianchuan) 贡献（[#18](https://github.com/WhiteNightShadow/camoufox-reverse-mcp/pull/18)）。

## 主要变更

- 新增 `tap_stage_calls`，默认关闭。它匹配 `return fn.apply(this, [状态号].concat(Array.prototype.slice.call(arguments)))` 这一种写法，改写后调用结果不变；每个状态返回时记录一条 `tap_stage` 事件，带状态号 `p`、参数个数、前三个参数和返回值的预览。
- `instrumentation(action="log")` 的 `summary` 新增 `hot_stages`，按状态号统计次数；`type_filter="tap_stage"` 只看阶段事件，`key_filter` 可以按状态号筛选。
- 文件解析失败时阶段插桩照样生效，这时 `instrumentation(action="status")` 的 `last_mode_used` 显示 `ast (stage taps only)`，`last_error` 给出解析失败的原因。文件能解析时只改写真正的 return 语句，字符串里同样的文字不会被改动。
- 同时开 `include_source_site` 时，阶段事件和普通 tap 的位置都对应原始脚本的偏移、行和列。

## 兼容性

- 新参数默认关闭，不开时改写结果和 v1.9.3 相同。工具还是 39 个，`instrumentation` 多一个参数，日志多一种事件类型和 `hot_stages` 字段。
- 只认上面那一种调用写法，其他写法原样保留。事件在状态返回时记录，所以嵌套的状态排在前面；抛出异常的状态不记录。
- regex 模式和解析失败的文件没有语法树可以核对，写在字符串里的同样文字也会被改写，写在双引号字符串里时脚本会报语法错误。能解析的文件请用默认的 `mode="ast"`。

## 验证

- 完整离线回归：本机 Python 3.12、Camoufox 0.5.9 与 Playwright 1.62.0 为 501 passed、2 skipped；CI 上 Python 3.10 和 3.12 分别配三组依赖（Camoufox 0.4.11 与 Playwright 1.52.0、0.5.5 与 1.60.0、0.5.9 与 1.62.0）全部通过，Windows 和 macOS 的平台回归与 uvx 安装检查也都通过。
- 新增 19 个测试（贡献者 7 个，合并前补了 12 个）。用一个小型平坦化 VM 在 Node 里对照：ast、ast 加默认 tap、regex 三种改写下，计算结果、`this`、参数个数、抛出的异常都和不改写时相同，参数数组也没有被改动，阶段事件按调用顺序记录。其余测试覆盖指令序言的位置、字符串里的同样写法、源码位置映射、解析失败时的状态显示和按状态号筛选。
- 真实浏览器（Camoufox 0.5.9，无头，本地页面）：同一个 VM 脚本插桩前后计算结果一致，记录到 11 条阶段事件、5 个状态，ast 和 regex 模式结果相同。去掉 Node 让文件解析失败时只做阶段插桩，状态里显示 `ast (stage taps only)`。字符串里写了同样调用的脚本、开头是字符串且下一行接着写代码的脚本都能正常运行；日志返回的源码位置都能对回原始脚本。
- 贡献者在一个 315 KB 的真实安全 SDK 上验证：改写 169 处分发调用，一次计算产生 754 条阶段事件、51 个状态，生成的 token 和改写前一致。
